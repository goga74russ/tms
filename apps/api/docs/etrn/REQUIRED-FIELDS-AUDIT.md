## Не master-data (не делаем «обязательным у роли»)

Захватывается при формировании документа / per-trip:
- Факты погрузки (`СвПогруз`: заявл./факт. прибытие-убытие) — события рейса.
- Одометр выезд/заезд (ЭПЛ) — `waybills.odometerOut/In`.
- ЭП цепочек титулов/ЭЗЗ/ЭПЛ — placeholder до КЭП (Контур).
- Лицензия медорганизации (ЭПЛ-медосмотры) — только алко-ниша, сущности нет.

## Фазы

- **Фаза 1 (миграция 0059, готово):** добавлены недостающие колонки (additive,
  nullable). Генераторы (`/etrn`, `/epl`, `/orders/:id/ezz`) пробрасывают их:
  телефон перевозчика — `organizations.phone` → инициатор; телефон/серия/дата ВУ/ИНН
  водителя — из `drivers`; габариты — из `orders`.
- **Фаза 2 (валидация форм) — ГОТОВО (жёстко):** поля обязательны при создании/
  редактировании на уровне приложения (Zod-схемы в @tms/shared — общие для API и веба
  + формы), НЕ DB `NOT NULL` (legacy-строки не ломаем). Сделано:
  - Водитель: серия/дата ВУ, ИНН, телефон (Create+Update).
  - ТС: вместимость (Create).
  - Контрагент: телефон (Create).
  - Организация: ОГРН, юр.адрес, телефон (онбординг ProfileSchema; phone — новая колонка).
  - Заказ: места, дата погрузки — обязательны при создании (Create). **Габариты места
    (В×Д×Ш) — НЕ при создании**, а при ВЫПУСКЕ ЭЗЗ (`generateEZZShipper` → 422):
    дозаполняются ровно когда нужны. На карточке заказа — бейдж «габариты не заполнены
    — потребуются для ЭЗЗ». Снижает трение на не-ЭЗЗ заказах.
  - Пользователь: НЕ форсируем — контакт перевозчика закрыт `organizations.phone`
    (обязателен), а `users.phone` был лишь фолбэком; жёстко требовать телефон на
    регистрации (включая водителей-юзеров) — трение без пользы. Подписант = `users.fullName`.
- **Фаза 3 (опц.):** после бэкфилла legacy — `NOT NULL` на уровне БД.
