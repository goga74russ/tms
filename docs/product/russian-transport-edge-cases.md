# Backlog операционных edge cases РФ

Обновлено: 2026-04-28

Этот список нужен, чтобы TMS v2 не стала системой только для happy path `одна заявка -> одна машина -> одна доставка`. Многие реальные перевозки ломают такую модель: груз делится, консолидируется, меняется по факту, требует особых условий, документов, разрешений или претензионного контура.

## P1. Частые операционные сценарии

| Сценарий | Пример из жизни | Что должен уметь продукт | Сейчас |
|---|---|---|---|
| Одна заявка -> несколько рейсов | 100 тонн, машины по 20 тонн | Делить заказ на партии/сегменты, считать остаток, закрывать частями | * Нет полноценной модели сегментов заказа |
| Один рейс -> несколько заявок | Машина забирает 3 заказа у разных клиентов | Консолидировать партии, вести отдельные документы/статусы/биллинг по каждой заявке | Требует проверки модели `trip_orders` и UI |
| Частичная погрузка | План 20 тонн, загрузили 18.7 | Фиксировать факт, причину, фото/подписи, пересчет остатка и тарифа | * Нет mature actuals по весу/количеству |
| Частичная доставка | Получатель принял 17 из 18 паллет | Отразить недостачу, акт, claim, финансовый резерв | * Нет полноценной связки доставка -> претензия |
| Мультистоп | Один рейс с несколькими погрузками/выгрузками | Последовательность точек, SLA по каждой точке, документы по каждой партии | Route points есть, но нужен сильный workflow |
| Переадресация | Получателя/адрес меняют в пути | Версионировать маршрут, согласование, документальный след, ЭТРН-титул переадресовки | Не закрыто как отдельный процесс |
| Отмена после подачи ТС | Машина приехала, груз не готов | Фиксировать подачу, простой/штраф, акт, оплату | Нужен модуль претензий/штрафов |
| Простой на погрузке/выгрузке | Машина стоит 8 часов на складе | Тайминг прибытия/убытия, норматив, начисление, доказательства | Нет end-to-end начисления простоя |
| Замена машины/водителя | Поломка, заболел водитель, другой тягач | История замен, перепроверка готовности, обновление документов | Нужен явный workflow замены |
| Поломка в пути | Рейс не может продолжаться | Инцидент, эвакуация/ремонт, перегруз в другую машину, уведомления | Ремонт есть, но не связан с disruption flow |
| Возврат груза | Получатель отказался или часть возвращается | Обратный рейс/сегмент, новые документы, финансовые последствия | Не выделено в доменной модели |
| Возврат ТС после рейса | Машина должна сдать документы, пройти осмотр, топливо/одометр | Послерейсовый чеклист и блокировка следующего рейса при проблемах | Не закрыто как обязательный этап |

## P2. Грузовые ограничения и совместимость

| Сценарий | Продуктовое требование | Почему важно |
|---|---|---|
| Перегруз по массе | Проверка веса груза, массы ТС, прицепа, осевых ограничений | Штрафы, запрет движения, невозможность спецразрешения для делимого тяжеловесного груза |
| Объемный груз | Учитывать м3, паллеты, длину/ширину/высоту, способ размещения | Машина может пройти по тоннам, но не пройти по объему/габаритам |
| Тип кузова | Тент, реф, изотерм, борт, самосвал, цистерна, контейнеровоз | Неверный кузов делает перевозку невозможной или рискованной |
| Температурный режим | Требования груза, возможности рефа, температурный лог, отклонения | Скоропортящиеся грузы требуют режима и доказательств соблюдения |
| Несовместимые грузы | Запрет совместной перевозки определенных категорий | Сборный рейс может быть запрещен по товарному соседству |
| Опасный груз | Класс опасности, ДОПОГ/ADR, допуск водителя/ТС, документы, маршрут | Отдельные требования к перевозке и ответственности |
| Крупногабарит/тяжеловес | Спецразрешение, маршрут, ограничения дорог, сопровождение | Нужен отдельный permit workflow |
| Ценный груз | Объявленная ценность, страхование, пломбы, контроль доступа | Влияет на ответственность, маршрут и документы |
| Хрупкий груз | Упаковка, крепление, фото до/после, акты повреждений | Доказательная база при претензиях |
| Наливной/сыпучий груз | Единицы измерения, тара/нетто/брутто, потери, промывка/очистка | Отличается от паллетной логики |

## P3. Документы и юридический контур

| Сценарий | Что нужно учесть |
|---|---|
| Бумажное исключение после 2026-09-01 | Система должна явно знать, почему документ оформлен на бумаге, а не в ЭПД. |
| Несколько участников | Грузоотправитель, грузополучатель, перевозчик, экспедитор, плательщик, фактический склад могут различаться. |
| Подписание разными сторонами | Нужны роли подписантов, КЭП/УКЭП/МЧД, полномочия и история подписания. |
| Отказ от подписи | Нужно фиксировать отказ, причину, акт/доказательства и дальнейший статус. |
| Потерянные бумажные документы | Missing docs queue, ответственный, дедлайн, финансовая блокировка. |
| ЭПД callback/retry | Идемпотентность, квитанции, отклонения, повторная отправка, сверка финального статуса. |
| Архив документов | Сроки хранения, неизменяемость, поиск по заказу/рейсу/контрагенту. |

## P4. Исполнение, контроль и мобильное приложение

| Сценарий | Что нужно в продукте |
|---|---|
| Нет связи у водителя | Offline queue, локальные фото/подписи, повторная синхронизация, конфликт-резолюция. |
| Фото плохого качества | Retake flow, минимальные требования, привязка к точке/времени/GPS. |
| GPS расходится с ручным статусом | Алгоритм доверия, флаг на диспетчера, audit trail. |
| Водитель нажал не тот статус | Корректировка с причиной и правами, без потери истории. |
| Нарушение ETA | Автоуведомление, причина задержки, влияние на SLA/штраф. |
| Режим труда и отдыха | Интеграция с тахографом или хотя бы контроль риска переработки. |
| Два водителя | Экипаж, смены, подписи, путевой лист, ответственность. |
| Прицеп меняется отдельно от тягача | История сцепок, готовность прицепа, документы прицепа. |

## P5. Финансы, претензии, закрытие

| Сценарий | Что нужно в продукте |
|---|---|
| Простой | Норматив, факт, подтверждение, автоматическое начисление или claim. |
| Штраф за срыв подачи | Кто виноват, доказательства, сумма, акт, settlement. |
| Недостача/повреждение | Акт, фото, стоимость груза, ответственная сторона, резерв, итоговое решение. |
| Частичная оплата | Разделение счета по выполненным сегментам/рейсам. |
| Допуслуги | Погрузка, разгрузка, пропуск, мойка, простой, экспедирование. |
| Несовпадение с 1С | Сверка актов/счетов, статусы выгрузки, расхождения. |
| Закрытие рейса без документов | Правило: разрешать с риском или блокировать до сдачи досье. |

## Что делать первым

1. Ввести доменную модель партий/сегментов заказа.
2. Добавить фактические значения погрузки/доставки: вес, объем, места, паллеты, фото, подпись, расхождение.
3. Сделать матрицу совместимости груза и ТС.
4. Сделать досье документов как обязательный close gate.
5. Сделать модуль инцидентов/претензий, связанный с рейсом, заказом, документами и финансами.
6. Сделать dispatcher cockpit исключений: перегруз, опоздание, нет документов, нет связи, расхождение, простой, претензия.
