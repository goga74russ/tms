# Backlog операционных edge cases РФ

Обновлено: 2026-04-29

Этот список нужен, чтобы TMS v2 не стала системой только для happy path `одна заявка -> одна машина -> одна доставка`. Реальные перевозки часто ломают такую модель: груз делится, консолидируется, меняется по факту, требует особых условий, документов, разрешений или претензионного контура.

Колонка `Работа` используется как живой трекер: `сделано + дата` означает, что есть код/документация/проверка в `TMS-prod`; `частично` означает, что фундамент есть, но сценарий еще нельзя считать закрытым end-to-end.

## P1. Частые операционные сценарии

| Сценарий | Пример из жизни | Что должен уметь продукт | Сейчас | Работа |
|---|---|---|---|---|
| Одна заявка -> несколько рейсов | 100 тонн, машины по 20 тонн | Делить заказ на партии/сегменты, считать остаток, закрывать частями | Есть модель `shipment_lots`, `trip_lot_assignments`, read/write API, smoke 100 тонн -> 2 рейса | Сделано 2026-04-29; нужно UI и больше кейсов |
| Один рейс -> несколько заявок | Машина забирает 3 заказа у разных клиентов | Консолидировать партии, вести отдельные документы/статусы/биллинг по каждой заявке | `trip_orders` и route points есть, модель партий поддерживает несколько заказов в рейсе | Частично 2026-04-29; нужен отдельный smoke/UI |
| Частичная погрузка | План 20 тонн, загрузили 18.7 | Фиксировать факт, причину, фото/подписи, пересчет остатка и тарифа | Есть `shipment_facts` по весу/объему/местам, пересчет lot totals | Частично 2026-04-29; нужны фото/подпись/тариф |
| Частичная доставка | Получатель принял 17 из 18 паллет | Отразить недостачу, акт, claim, финансовый резерв | Есть фактическая разгрузка, shortage, авто-претензия, smoke на недовоз 1 тонны | Частично 2026-04-29; нужны акт, резерв, финансы |
| Мультистоп | Один рейс с несколькими погрузками/выгрузками | Последовательность точек, SLA по каждой точке, документы по каждой партии | Route points создаются при назначении партии | Частично 2026-04-29; нужен workflow точек и SLA |
| Переадресация | Получатель/адрес меняются в пути | Версионировать маршрут, согласование, документальный след, ЭТРН-титул переадресовки | Есть API изменения route point, journal event, cockpit signal, ЭТРН Title 03 metadata | Сделано, проверено 2026-04-29; нужен UI согласования |
| Отмена после подачи ТС | Машина приехала, груз не готов | Фиксировать подачу, простой/штраф, акт, оплату | Базовые claims есть, но причины/начисления не выделены | Ожидает |
| Простой на погрузке/выгрузке | Машина стоит 8 часов на складе | Тайминг прибытия/убытия, норматив, начисление, доказательства | Не закрыто end-to-end | Ожидает |
| Замена машины/водителя | Поломка, заболел водитель, другой тягач | История замен, перепроверка готовности, обновление документов | Есть API замены ТС/водителя/прицепа, compatibility recheck, journal event, cockpit signal, ЭТРН Title 04 metadata | Сделано, проверено 2026-04-29; нужен UI согласования |
| Поломка в пути | Рейс не может продолжаться | Инцидент, эвакуация/ремонт, перегруз в другую машину, уведомления | Ремонты есть, но не связаны с disruption flow | Ожидает |
| Возврат груза | Получатель отказался или часть возвращается | Обратный рейс/сегмент, новые документы, финансовые последствия | `shipment_facts.factType=return` есть, но доменный процесс не выделен | Частично 2026-04-29 |
| Возврат ТС после рейса | Машина должна сдать документы, пройти осмотр, топливо/одометр | Послерейсовый чеклист и блокировка следующего рейса при проблемах | Не закрыто как обязательный этап | Ожидает |

## P2. Грузовые ограничения и совместимость

| Сценарий | Продуктовое требование | Почему важно | Работа |
|---|---|---|---|
| Перегруз по массе | Проверка веса груза, массы ТС, прицепа, осевых ограничений | Штрафы, запрет движения, невозможность спецразрешения для делимого тяжеловесного груза | Частично 2026-04-29: есть проверка payload capacity при назначении партии; осей/разрешений нет |
| Объемный груз | Учитывать м3, паллеты, длину/ширину/высоту, способ размещения | Машина может пройти по тоннам, но не пройти по объему/габаритам | Частично 2026-04-29: объем/места есть в lots/facts; габаритов и укладки нет |
| Тип кузова | Тент, реф, изотерм, борт, самосвал, цистерна, контейнеровоз | Неверный кузов делает перевозку невозможной или рискованной | Частично 2026-04-29: есть read-only compatibility check по bodyType/vehicleRequirements; нужна полноценная матрица |
| Температурный режим | Требования груза, возможности рефа, температурный лог, отклонения | Скоропортящиеся грузы требуют режима и доказательств соблюдения | Частично 2026-04-29: есть проверка признаков temperature/ref; температурного лога и датчиков нет |
| Несовместимые грузы | Запрет совместной перевозки определенных категорий | Сборный рейс может быть запрещен по товарному соседству | Ожидает |
| Опасный груз | Класс опасности, ДОПОГ/ADR, допуск водителя/ТС, документы, маршрут | Отдельные требования к перевозке и ответственности | Ожидает |
| Крупногабарит/тяжеловес | Спецразрешение, маршрут, ограничения дорог, сопровождение | Нужен отдельный permit workflow | Ожидает |
| Ценный груз | Объявленная ценность, страхование, пломбы, контроль доступа | Влияет на ответственность, маршрут и документы | Ожидает |
| Хрупкий груз | Упаковка, крепление, фото до/после, акты повреждений | Доказательная база при претензиях | Частично 2026-04-29: damage -> claim; доказательная база не закрыта |
| Наливной/сыпучий груз | Единицы измерения, тара/нетто/брутто, потери, промывка/очистка | Отличается от паллетной логики | Ожидает |

## P3. Документы и юридический контур

| Сценарий | Что нужно учесть | Работа |
|---|---|---|
| Бумажное исключение после 2026-09-01 | Система должна явно знать, почему документ оформлен на бумаге, а не в ЭПД | Частично 2026-04-29: dossier item exception и closeGate `paperException`; нет юридического справочника оснований |
| Несколько участников | Грузоотправитель, грузополучатель, перевозчик, экспедитор, плательщик, фактический склад могут различаться | Частично: dossier собирает стороны; нужна ролевая модель ЭТРН |
| Подписание разными сторонами | Нужны роли подписантов, КЭП/УКЭП/МЧД, полномочия и история подписания | Ожидает; долг записан в `etrn-source-map.md` |
| Отказ от подписи | Нужно фиксировать отказ, причину, акт/доказательства и дальнейший статус | Ожидает |
| Потерянные бумажные документы | Missing docs queue, ответственный, дедлайн, финансовая блокировка | Частично 2026-04-29: `document_dossier_items`, exception endpoint и close gate есть; очереди ответственных нет |
| ЭПД callback/retry | Идемпотентность, квитанции, отклонения, повторная отправка, сверка финального статуса | Частично 2026-04-29: `transport_document_exchanges/receipts` есть; per-title ЭТРН еще нет |
| Архив документов | Сроки хранения, неизменяемость, поиск по заказу/рейсу/контрагенту | Частично: MinIO/storage skeleton есть; юридический архив XML/подписей не закрыт |
| ЭТРН source package | Реализация должна опираться на локальные XSD и описание формата | Сделано 2026-04-29: `docs/architecture/etrn-source-map.md` |
| ЭТРН dossier projection | В досье рейса должен быть виден обязательный ЭТРН-контур | Сделано 2026-04-29: `dossierItems`, placeholder `etrn`, close gate по missing/exceptioned |

## P4. Исполнение, контроль и мобильное приложение

| Сценарий | Что нужно в продукте | Работа |
|---|---|---|
| Нет связи у водителя | Offline queue, локальные фото/подписи, повторная синхронизация, конфликт-резолюция | Частично 2026-04-29: execution events принимают `clientEventId`, `offlineCreatedAt`, attachments; полноценной mobile offline queue нет |
| Фото плохого качества | Retake flow, минимальные требования, привязка к точке/времени/GPS | Частично 2026-04-29: execution events принимают attachment placeholders + GPS; retake/quality workflow нет |
| GPS расходится с ручным статусом | Алгоритм доверия, флаг на диспетчера, audit trail | Частично 2026-04-29: GPS пишется в journal рядом с событием; алгоритма доверия/флага диспетчеру нет |
| Водитель нажал не тот статус | Корректировка с причиной и правами, без потери истории | Частично 2026-04-29: есть `correction` execution event в append-only journal; workflow согласования нет |
| Нарушение ETA | Автоуведомление, причина задержки, влияние на SLA/штраф | Частично 2026-04-29: есть `delay` execution event с причиной; SLA/штрафы не рассчитываются |
| Режим труда и отдыха | Интеграция с тахографом или хотя бы контроль риска переработки | Ожидает |
| Два водителя | Экипаж, смены, подписи, путевой лист, ответственность | Ожидает |
| Прицеп меняется отдельно от тягача | История сцепок, готовность прицепа, документы прицепа | Частично: trailer scope есть; workflow сцепок нет |

## P5. Финансы, претензии, закрытие

| Сценарий | Что нужно в продукте | Работа |
|---|---|---|
| Простой | Норматив, факт, подтверждение, автоматическое начисление или claim | Частично 2026-04-29: есть `downtime` execution event и claim cause/exposure; нормативов и начисления нет |
| Штраф за срыв подачи | Кто виноват, доказательства, сумма, акт, settlement | Частично 2026-04-29: claims поддерживают cause/reserve/estimated/settlementNote; акта и правил начисления нет |
| Недостача/повреждение | Акт, фото, стоимость груза, ответственная сторона, резерв, итоговое решение | Частично 2026-04-29: auto claim из shortage/damage/refusal; акты/резервы не закрыты |
| Частичная оплата | Разделение счета по выполненным сегментам/рейсам | Ожидает |
| Допуслуги | Погрузка, разгрузка, пропуск, мойка, простой, экспедирование | Ожидает |
| Несовпадение с 1С | Сверка актов/счетов, статусы выгрузки, расхождения | Ожидает |
| Закрытие рейса без документов | Правило: разрешать с риском или блокировать до сдачи досье | Частично 2026-04-29: dossier projection и close gate есть; нужен UI/workflow закрытия рейса |
