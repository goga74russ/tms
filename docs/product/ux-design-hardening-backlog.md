# UX / Design Hardening Backlog

Updated: 2026-05-14 (round 2 — i18n hardening после пилот-деплоя)

Цель: довести TMS v2 от функционально крепкой коробки до интерфейса, который можно уверенно показывать заказчику. Этот backlog не про внешние платные сервисы, а про бесплатную полировку сценариев, навигации, демо-данных и читаемости.

## Принятые решения

- Нужен отдельный дизайн-аудит и UX backlog после функционального hardening.
- Для `admin` и `super-user` не делаем стартом диспетчерскую. Нужна нормальная главная страница для всех пользователей: вход в продукт, краткое описание компании/системы, ролевые рабочие места, ключевые показатели и быстрые переходы.
- Досье рейса не дробим на жесткие вкладки `Обзор / Операции / Документы`. Вместо этого делаем сворачиваемые шторки/секции: в шапке секции всегда остается краткая сводка, а детали можно раскрывать по необходимости.

## Проверка готовности к демо

- Супер-юзер видит главную страницу, а не техническую админку.
- Водительский сценарий честно объяснен: mobile-only или web read-only.
- Претензия создается без ручного UUID.
- Диспетчерская не ломается без внешней карты/геопоиска.
- Финансы показывают контрагента и период.
- Аналитика показывает выбранное окно анализа.
- Досье рейса раскрывается постепенно через шторки, но важные счетчики видны в шапках.

### RBAC (`auth/rbac.ts`) — Сделано 2026-05-14

`requireAbility()` раньше возвращал `Нет доступа: read KPI` — английский
action + Subject leak. Теперь Action и Subject пропускаются через
русские карты `ACTION_LABELS` / `SUBJECT_LABELS`:
- `read KPI` → `просмотр панели KPI`
- `manage Order` → `управление заявок`
- `delete Trip` → `удаление рейсов`

Response теперь: `{ error: "Недостаточно прав: ...", code: "ABILITY_DENIED",
action, subject }`. Поле `code` позволяет фронту branching без парсинга
русского текста.

### Web API client (`lib/api.ts`) — Сделано 2026-05-14

Добавлен `translateApiError()`:
- Известные коды (`PLAN_FEATURE_LOCKED`, `PLAN_LIMIT_EXCEEDED`,
  `ABILITY_DENIED`, `Unauthorized`, `Forbidden`) → русские сообщения
- Кириллические ответы (server уже локализован) → проброс as-is
- Прочее → `Ошибка: ...` или `Ошибка запроса (HTTP NNN)`

Plan-guard 402-коды (`PLAN_FEATURE_LOCKED`, `PLAN_LIMIT_EXCEEDED`)
осознанно оставлены как machine-readable codes — они нужны Paywall
modal'у для условного рендера. Человеко-читаемый текст теперь даёт
client translation layer.
