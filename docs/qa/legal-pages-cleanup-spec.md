## §1 Корневая причина

Загрузчик `apps/web/src/lib/legal-docs.ts` (и страницы, его использующие) рендерит **весь markdown-файл целиком**, включая служебные секции:

1. **YAML-frontmatter** в начале файла (`--- ... ---`) — машинные метаданные, не контент.
2. **Блоки «## Комментарии для применения (не печатать)»** в конце документов — мои (Jurist) внутренние заметки.
3. **Плейсхолдеры `{{NAME}}`** в etrn-шаблонах — поля для подстановки реквизитов клиента, не готовый текст.

## §2 Задачи для TransPult (код)

### 🔴 T-LEGAL-1 — Срезать frontmatter при рендере

**Файл:** `apps/web/src/lib/legal-docs.ts`

**Проблема:** YAML-блок между первыми `---` и `---` рендерится как текст (видно `provider_id`, `version:`, `effective_from` на `/legal/dpa`).

**Фикс:** перед рендером markdown удалять frontmatter. Стандартный паттерн:
```ts
function stripFrontmatter(md: string): string {
  // Frontmatter = блок между первыми двумя --- в начале файла
  if (md.startsWith('---')) {
    const end = md.indexOf('\n---', 3);
    if (end !== -1) return md.slice(md.indexOf('\n', end + 4) + 1);
  }
  return md;
}
```

**Acceptance:** на `/legal/dpa` и любой `/legal/dpa/[slug]` нет строк `provider_id`, `version:`, `effective_from`, `requires_acceptance`, `owner:`, `category:`.

### 🔴 T-LEGAL-2 — Срезать блок «Комментарии для применения (не печатать)»

**Файл:** `apps/web/src/lib/legal-docs.ts`

**Проблема:** в конце многих markdown-документов есть секция, явно помеченная «не печатать» — она для внутреннего применения, но публикуется.

**Фикс:** при рендере обрезать всё от маркера внутренней секции до конца файла. Маркеры (срезать по первому встреченному):
```ts
const INTERNAL_MARKERS = [
  '## Комментарии для применения',   // «(не печатать)»
  '## Комментарии (не печатать)',
  '<!-- internal -->',
];
function stripInternal(md: string): string {
  for (const marker of INTERNAL_MARKERS) {
    const idx = md.indexOf(marker);
    if (idx !== -1) return md.slice(0, idx).trimEnd();
  }
  return md;
}
```

> **Согласовано с Jurist:** Jurist параллельно унифицирует заголовок этих блоков во всех документах к единому виду `## Комментарии для применения (не печатать)`, чтобы маркер срабатывал гарантированно. Список документов с такими блоками — см. §4.

**Acceptance:** на `/legal/cookies`, `/legal/refunds`, всех `/legal/etrn/[slug]`, `/legal/dpa/[slug]` — нет текста «не печатать», «ТЗ для TransPult», «Web-route», «TODO», «transpult».

### 🔴 T-LEGAL-3 — Страница `/legal/etrn` → витрина-каталог (НЕ дамп шаблонов)

**Файлы:** `apps/web/src/app/legal/etrn/page.tsx` (index) + `apps/web/src/app/legal/etrn/[slug]/page.tsx`

**Проблема:** etrn-документы — это **типовые формы с плейсхолдерами** (`{{CEO_NAME}}`, `{{ORG_INN}}` и т.д.) для подстановки реквизитов конкретного клиента. Показывать их как готовую веб-страницу с сырыми `{{...}}` юридически некорректно (документ с незаполненными существенными реквизитами ничтожен) и выглядит как баг.

**Решение (выбрано владельцем):** **витрина-каталог.**

`/legal/etrn` (index) должна показывать:
- Заголовок «Юридический пакет для перехода на ЭПД (к 01.09.2026)»
- Краткое описание (1 абзац): что это, зачем, для кого
- **Список документов пакета** (название + 1 строка назначения), БЕЗ полного текста с плейсхолдерами:
  1. Приказ о переходе на ЭПД
  2. Регламент работы с ЭПД
  3. Допсоглашение к договору перевозки
  4. Допсоглашение к договору транспортной экспедиции
  5. Согласие сотрудника на использование КЭП
  6. Согласие водителя на Госключ
  7. Соглашение об использовании ПЭП
  8. Положение об электронной подписи
  9. DPA «Клиент ↔ TMS»
- **Кнопка «Скачать пакет» / «Получить шаблоны»** — ведёт на мастер заполнения в кабинете (если есть) либо на скачивание (когда будет реализован экспорт). Пока мастера нет — кнопка-заглушка «Доступно после регистрации организации» или ссылка на онбординг.

**`/legal/etrn/[slug]`** (отдельный документ):
- **Вариант A (рекомендуется):** заменять плейсхолдеры `{{...}}` на визуальные плейсхолдеры `[поле: наименование организации]`, `[ФИО руководителя]` и т.п. — чтобы было видно, что это форма для заполнения, а не сырой шаблон с фигурными скобками.
- Маппинг плейсхолдер → человекочитаемая метка — см. §3.
- Frontmatter и «не печатать»-блоки срезаны (T-LEGAL-1, T-LEGAL-2).

**Acceptance:** на `/legal/etrn` нет ни одной `{{...}}`-конструкции и слова «Placeholder»; index показывает список из 9 документов + CTA; `/legal/etrn/[slug]` показывает текст с человекочитаемыми `[метками]` вместо `{{}}`.

### 🔴 T-LEGAL-3b — index-страницы НЕ должны рендерить технический README.md

**Файлы:** `apps/web/src/app/legal/etrn/page.tsx`, `apps/web/src/app/legal/dpa/page.tsx`, `apps/web/src/lib/legal-docs.ts`

**Проблема (важно):** index-страницы `/legal/etrn` и `/legal/dpa` сейчас рендерят `README.md` соответствующей папки. Но `docs/legal/etrn/README.md` и `docs/legal/dpa/README.md` — это **технические README для команды**, содержат:
- `## TODO для TransPult` (dpa/README.md:95)
- «TransPult: при коммите изменения... CI должен прогонять...» (dpa/README.md:65)
- таблицы placeholders, frontmatter-инструкции, версионирование

Это **внутренняя документация процесса**, не контент для клиента. Её нельзя показывать на публичной странице.

**Фикс:** index-страницы строят список документов **программно** (из имён файлов + захардкоженных человекочитаемых названий, см. T-LEGAL-3), а **НЕ** рендерят `README.md`. README остаётся в репозитории как dev-документ, но не публикуется.

**Acceptance:** на `/legal/etrn` и `/legal/dpa` нет текста «TODO для TransPult», «CI должен», «placeholders», нет таблиц с frontmatter-полями.

### 🟡 T-LEGAL-4 — DPA-каталог: проверить тот же класс

**Файлы:** `apps/web/src/app/legal/dpa/page.tsx` + `[slug]/page.tsx`

После T-LEGAL-1/2 проверить, что на `/legal/dpa/[slug]` (diadoc, gosklyuch, wialon, yookassa, kontur-sign, mailru-smtp, anthropic-ai) не осталось:

**Acceptance:** `/legal/dpa/[slug]` — чистый текст DPA без метаданных и внутренних пометок.
