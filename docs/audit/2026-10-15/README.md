# Аудит TMS «ТрансПульт» — 2026-10-15

Комплексный аудит монорепозитория по модели «автономной компании». Десять ролей-экспертов (CTO, Security, Backend, Юрист, Frontend, Mobile, QA, DevOps, Product/UX, Business) независимо проверили код, конфигурацию и документы. Затем «совет директоров» (CEO + Inversion/pre-mortem) свёл их выводы в единый консенсус. Аудит проводился на коде HEAD `4598a71` (последний продуктовый коммит 2026-07-03).

> ⚠️ **Конфиденциально.** Отчёты описывают ещё не закрытые уязвимости и сценарии их эксплуатации. Их нельзя хранить в публичном репозитории (см. C-02 в консенсусе). Значения секретов в отчётах не приводятся, указаны только места, где они лежат.

## Как читать

1. Начинайте с **[00-consensus.md](00-consensus.md)**. В нём решение совета GO/NO-GO, сквозные темы, единый реестр блокеров C-01…C-27, pre-mortem, Next Action и решения, которые остаются за владельцем.
2. За деталями конкретного блокера переходите по исходным ID (например `SEC-01`, `MOB-03`) в ролевой отчёт. Там указаны `file:line`, сценарий, исправление и статус проверки.
3. P2/P3 в консенсус не сведены. Их первоисточник — ролевые отчёты, раздел «Находки».

## Легенда severity

| Уровень | Значение | Срок |
|---|---|---|
| **P0** | Блокер запуска: утечка данных, потеря денег, юридическая недействительность | Немедленно (День 0 / Неделя 1) |
| **P1** | Серьёзный дефект | До пилота |
| **P2** | Важно | Ближайший спринт |
| **P3** | Улучшение | По возможности |

**Статус находки:** `CONFIRMED` — подтверждено повторным чтением кода или прогоном; `PLAUSIBLE` — вероятно, но зависит от рантайма или конфигурации прода, которые из репозитория не видны. Пометка «повтор» означает находку из прошлого аудита, которая до сих пор не закрыта.

**ID:** `CTO-`, `SEC-`, `BE-`, `LEG-`, `WEB-`, `MOB-`, `QA-`, `OPS-`, `UX-`, `BIZ-` — ID ролей; `C-NN` — ID кластера консенсуса; `H-NN` — решение, которое принимает только владелец (Human Override).

## Метод

1. **Общий бриф.** Задаёт правила: только чтение кода, формат находки (Где / Что / Сценарий / Исправление / Статус), шкалу severity.
2. **10 независимых ролей.** Каждая читает код, конфиги и документы со своей точки зрения. QA дополнительно прогнал unit-тесты, интеграционные тесты на живых PG16 + Redis, smoke-chain и проверку дрейфа OpenAPI.
3. **Адверсариальная самопроверка.** Каждую находку автор перечитывает и пытается опровергнуть. Ложное срабатывание считается хуже пропуска.
4. **Сверка с прошлыми аудитами.** Сверены `docs/qa/code-audit-2026-06-14.md`, `docs/qa/remediation-tracker.md`, `docs/operations/audit-2026-05-12-deep.md`, `docs/product/full-audit-2026-05-28.md`, `docs/legal/compliance-register-2026-06-11.md` и проверено, что из них закрыто на самом деле.
5. **Синтез.** Дедупликация находок в кластеры C-NN, сквозные темы, разбор противоречий между ролями, повторная проверка всех P0 и спорных мест по `file:line`, pre-mortem, план действий.
