## §3 Чек-лист обязательных реквизитов УПД (Приказ ФНС ЕД-7-26/901@)

| # | Реквизит | Реализация |
|---|---|---|
| 1 | Заголовок «Универсальный передаточный документ» | ✅ Centered, fontWeight 700 |
| 2 | Статус документа (1 или 2) | ✅ Auto-detect: VAT-плательщик → статус 1, иначе 2 |
| 3 | Номер и дата УПД | ✅ |
| 4 | Все реквизиты СФ (если статус 1) | ✅ Реквизиты продавца/покупателя/валюты/основания |
| 5 | **Дата фактической отгрузки/оказания услуги** | ✅ Отдельная строка перед подписями |
| 6 | Таблица услуг с НДС-разбивкой | ✅ Идентично СФ |
| 7 | Подписи **передающей и принимающей сторон** | ✅ Раздельные блоки «передал» и «принял» с местом для должности и подписи |
| 8 | Должности подписантов | ⚠️ Поле «Должность: ___________________» оставлено для ручного заполнения. Для электронного варианта должно pre-fill через user-controller. См. §5. |
| 9 | Footer со ссылкой на нормативку | ✅ Приказ ФНС ЕД-7-26/901@ + упоминание возможности подписания КЭП |

**Замечание для УПД статуса 1:** в текущей реализации УПД-шаблон **не выделяет в отдельную строку** Грузоотправителя/Грузополучателя (как это делает SF-шаблон). Для УПД статуса 1, который заменяет связку СФ+акт, эти реквизиты **обязательны** по ПП РФ 1137 (ст. 169 ч. 5 НК). Это **минор-замечание** — на практике грузоотправитель = продавец, грузополучатель = покупатель в 95% случаев, и шаблон корректно дублирует эти данные неявно. Но **формально** при работе с трёхсторонними сделками (грузоотправитель ≠ продавец) шаблон надо доработать.

**Покрытие УПД:** 8 из 9 пунктов + 1 с замечанием. ⚠️ 1 пункт (отдельная строка грузоотправитель/грузополучатель для статуса 1) — для будущего улучшения.

## §5 Замечания для улучшения (не блокирующие acceptance)

### 5.1 Автозаполнение должностей в УПД

Поля «Должность: ___________________» в подписях УПД оставлены для ручного заполнения. В будущей версии:
- Pre-fill должности подписанта со стороны продавца (из user.position + roles).
- Pre-fill должности принимающей стороны (если известно из договора).

**Не блокирующее.** Бумажная форма УПД допускает ручное заполнение.

### 5.2 Грузоотправитель / Грузополучатель в УПД (статус 1)

Добавить в УПД-шаблон отдельную строку для Грузоотправителя/Грузополучателя по аналогии с SF-шаблоном — для случаев, когда они отличаются от Продавца/Покупателя.

**Не блокирующее.** В типовых сделках совпадают.

### 5.3 КЭП-плашка

После подключения реального провайдера КЭП (Контур.Подпись, СБИС, КриптоПро CADES) — добавить визуальную плашку «Подписано КЭП [ФИО сотрудника, реквизиты сертификата, дата]» внизу каждого шаблона.

**Не блокирующее.** До подключения провайдеров — заглушки достаточно.

### 5.4 Server-side PDF для batch-экспорта

Текущая реализация — через `window.print()`. Для batch-экспорта 100+ СФ за период (типовой запрос бухгалтерии при налоговой проверке) нужен server-side PDF.

**Не блокирующее.** На MVP достаточно client-side. Запрос от пилотных клиентов покажет необходимость.

### 5.5 Auto-routing кнопки «Печать»

В `/finance/page.tsx` нужна автоматическая маршрутизация: при клике «Печать» по строке invoice — открыть соответствующий шаблон в зависимости от `invoice.type` (sf → /print/sf/, upd → /print/upd/, corrective_sf → /print/corrective-sf/).

**Не блокирующее.** Это UI-удобство.
