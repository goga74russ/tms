## 🔴🔴 §0 КРИТИЧЕСКАЯ НАХОДКА — НДС 22% с 01.01.2026

**Источник:** Федеральный закон от 28.11.2025 № 425-ФЗ. Подтверждено: КонсультантПлюс, ГАРАНТ, БУХ.1С, OFD.ru, Точка Банк (8+ источников).

С **1 января 2026 года** основная ставка НДС повышена **с 20% до 22%**:
- Расчётная ставка: ~~20/120~~ → **22/122**
- Льготная ставка 10% — без изменений (продукты, детские товары и т.д.)
- УСН с НДС: ставки **5%** (доход до 250 млн ₽) и **7%** (250-450 млн ₽) — без изменений; либо общая **22%**
- Порог освобождения УСН от НДС снижен до **20 млн ₽** за 2025 год

**Сегодня 11.06.2026 — ставка 22% действует уже 5,5 месяцев.**

## 🔴 §0.1 ВТОРАЯ НАХОДКА — новая форма счёта-фактуры с 01.04.2026

**Источник:** изменения в Постановление Правительства РФ № 1137 (с 01.04.2026). Подтверждено: ГАРАНТ, Диадок, Главбух, МоёДело.

С **1 апреля 2026** действует обновлённая форма счёта-фактуры:
1. **Новая строка 5б** — для случаев реализации в счёт ранее полученной оплаты (с 01.01.2026).
2. **Новая графа 14** — стоимость товара, подлежащего прослеживаемости, без НДС.
3. **Для ИП** — реквизиты «свидетельства о госрегистрации ИП» заменены на **ОГРНИП + дата присвоения**.
4. Для прослеживаемых товаров — СФ/УПД только в электронном виде.

**Наши шаблоны SF и UPD (React + server) — на старой форме (до 01.04.2026).**

### 🔴 ТЗ для TransPult (P0 для СФ/УПД)

1. Добавить **строку 5б** в шаблоны sf/upd (React + server upd-pdf.ts).
2. Добавить **графу 14** (прослеживаемость) — для транспортных услуг обычно пусто, но графа должна присутствовать в форме.
3. Для ИП-исполнителя — выводить **ОГРНИП**, не «свидетельство о госрегистрации».

**Юр-импликация:** СФ на старой форме после 01.04.2026 — формальное нарушение, риск отказа в вычете НДС покупателю.

## §6 🔴 Рассинхрон двух путей печати (критично)

После прочтения роутов выдачи PDF подтверждено: **в системе два параллельных пути генерации одних и тех же документов, и они дают разный результат.**

### Карта путей

| Документ | Server-PDF путь (`GET .../pdf`) | React-print путь (`/print/*`) |
|---|---|---|
| Счёт | `/finance/invoices/:id/pdf` → `generateInvoicePdf` (finance/routes.ts:595) | `/print/invoice/[id]` |
| Акт | `/finance/invoices/:id/pdf` → `generateActPdf` (:617) | `/print/act/[id]` |
| УПД | `/finance/invoices/:id/pdf` → **`generateActPdf`** (:617, ветка «act or upd») | `/print/upd/[id]` |
| УПД (bulk) | `generateUpdPdf` (:909) | — |
| ТТН | `/orders/:id/ttn` → `generateTtnPdf` (orders/routes.ts:344) | `/print/ttn/[id]` |
| Путевой лист | `/waybills/:id/pdf` → `generateWaybillPdf` (waybills/routes.ts:424) | `/print/waybill/[id]` |
| Медосмотр | `/inspections/med/:id/pdf` → `generateMedInspectionPdf` | — (только server) |
| Техосмотр | `/inspections/tech/:id/pdf` → `generateTechInspectionPdf` | — (только server) |

### 🔴 Расхождения, дающие РАЗНЫЕ документы

**1. Реквизиты исполнителя:**
- Server-путь: `CARRIER` хардкод (pdf-base.ts:218, ИП Бардин из env).
- React-путь: `carrierRequisites` из API (организация документа).
- **Один клиент через две кнопки получит счёт от разных лиц** (если орг ≠ ИП Бардин).

**2. Ставка НДС:**
- Server-путь: `?? 20` хардкод default (act-pdf:35, invoice-pdf:34, upd-pdf:56). На finance/routes.ts:612 передаётся `invoice.vatRate` из БД, но БД-дефолт = `z.number().default(20)` (schemas.ts:105). Старые записи = 20%.
- React-путь: тоже `inv.vatRate`, но без явной коррекции на 22%.
- **Оба пути дают 20% по умолчанию** — см. §0 (должно быть 22%).

**3. УПД печатается как АКТ (server-путь):**
- finance/routes.ts:615-618 — для `invoice.type='upd'` на эндпоинте `/finance/invoices/:id/pdf` вызывается **`generateActPdf`** (заголовок «АКТ ВЫПОЛНЕННЫХ РАБОТ»), а не `generateUpdPdf`.
- React-путь имеет type-guard (закрыт), server-путь — **нет**.
- **Через server-PDF клиент получает УПД с заголовком «Акт»** — та же терминологическая каша, что я флажил в §1.1 print-documents-audit, но в серверном пути не исправлена.

**4. Путевой лист — обратное расхождение:**
- Server-путь (`generateWaybillPdf`) — **содержит** поля Приказа № 390 (реально заполняются из waybill-записи: issuedByName, validFrom/To, transportServiceType, transportMode, driverSnils — waybills/routes.ts:450-457).
- React-путь (`/print/waybill`) — **НЕ содержит** этих полей.
- **Server-путевой лист юр-корректен, React — нет.**

### 🔴 ТЗ для TransPult (P0)

1. **Выбрать ОДИН путь печати** для каждого документа (рекомендую server-PDF как единый — он централизован, не зависит от браузера, годится для batch).
2. Либо — если оба пути нужны (server для скачивания, React для предпросмотра) — **гарантировать идентичность**: общий источник реквизитов (org-requisites), общая ставка НДС, общий выбор шаблона по типу.
3. **finance/routes.ts:617** — для `type='upd'` вызывать `generateUpdPdf`, не `generateActPdf`.
4. Перевести server-PDF на `resolveOrgRequisites` (см. §2.F1).

**Юр-импликация:** клиент, скачавший «счёт» двумя кнопками и получивший два разных документа (разные реквизиты, разный НДС, УПД как «Акт») — это основание для спора о действительности и претензии. ФНС при проверке двух версий одного документа — повод для углублённой проверки.
