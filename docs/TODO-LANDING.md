## Отложено — добавить когда появится контент

### `/blog` (Блог)
**Когда делать:** когда будет 3+ готовых постов.
**Что нужно:** редакционный план, темы (например: «как читать UTII при пилоте», «что такое ЭТрН для маленького перевозчика», кейсы клиентов).
**Структура:** список постов с тегами, RSS/Atom, индивидуальные страницы по slug.
**Где жить:** Next.js content collection или внешний CMS (Tina/Sanity).

### `/docs` (Документация)
**Когда делать:** когда продукт стабилизируется (после первых 5-10 реальных пользователей).
**Что нужно:** Quick Start, разделы по ролям (логист / диспетчер / админ), интеграции (ЭДО, GPS, ОФД), API reference (OpenAPI уже есть).
**Структура:** MDX с навигацией, поиск (Algolia DocSearch или встроенный).
**Альтернатива:** inline-help внутри продукта (tooltips, side panels) — может быть достаточно.

### `/team` (Команда)
**Когда делать:** когда будут реальные люди в команде (минимум 2-3 человека помимо основателя).
**Что нужно:** ФИО, роль, фото, короткая био.
**Сейчас:** информация о единственном основателе живёт на `/about`.

## Не делать (зависимости / приоритет ниже)

- Статус системы — пока ручная страница `/status`. Полноценный uptime monitoring (с историей инцидентов) — отдельная задача, можно делать через uptime-kuma в отдельном контейнере или внешний сервис.
- Документация API — `ENABLE_API_DOCS=false` в prod. Когда понадобится — Swagger UI на `/api/docs` уже работает в dev. В prod включать только если есть публичные интеграторы.
